# 飞书消息小窗

## 2026-10-04 同步

桌面云端读取接口已迁移到 `https://leida.shenmiren.work/radar/api/robot-push/control`，继续使用本机加密保存的 ECDSA 私钥签名、时间戳和随机码验证。该精确接口使用服务端签名认证；网站其他页面仍使用 Cloudflare 邮箱验证。Cloudflare 规则是独立基础设施配置，拉取代码不会自动配置它。

首次连接和自动重连后从最新三条普通消息开始显示，避免逐条播放旧缓存导致时间落后；手动阅读期间不抢占位置，正常新增消息继续遵守停留时间。置顶消息保留来源的真实发送时间。

本次同步已验证：45 项核心检查、20 项 bridge 测试、云端读取及 WPF 窗口契约。实际安装窗口确认连接和持续接收，窗口最新消息时间与收到的最新消息一致。本仓库不包含本机密钥、用户配置、聊天消息或服务器凭据。

轻量 Windows WPF 小窗，通过飞书官方 Node SDK 长连接接收指定群的机器人新消息。白底黑字、默认微软雅黑、字号13，普通消息正文前两条逻辑文本行加粗，HTTP/HTTPS 链接可点击。普通成员消息不显示或响铃。

## 使用

- 正常启动紧贴当前屏幕工作区右上角，外边距为0。归位图标按实际消息高度调整至约三条；长消息超过屏幕时正常滚动，不裁切正文。窗口可拖动、缩放。
- 左上蓝灰开关控制逐条定时阅读，默认每条 15 秒，点击秒数可改为 1–300 秒。新消息不打断正在阅读的条目。手动滚动暂时暂停但保留开关开启；连续10秒没有滚轮、滚动按键或滚动条操作后，从当前可见条目重新开始完整停留时间。连续操作延后恢复，关闭开关或隐藏窗口取消恢复计时。队尾没有下一条时停止计时，隐藏到托盘时暂停阅读计时。
- 右上三根递增高度的小竖条显示真实连接状态（不是信号强度测量），详细原因见提示或设置。喇叭、置顶、设置、隐藏图标常驻；无机器人名称、ID、大标题或底部状态栏。
- 背景透明度 60–100%，仅白色背景变透明，文字、链接和图标保持不透明。设置窗口始终不透明。
- X 隐藏到右下角托盘，继续接收与响铃；真正退出在托盘菜单。主任务栏没有窗口按钮，同一用户只运行一个实例。
- 开机启动开关默认关闭，由用户打开后注册当前用户启动项。保存的应用配置可在启动时恢复连接。
- 声音只有开关，跟随系统音量。可导入有权使用的本地 WAV/MP3（不超过 2 MB）。不附带第三方音频，不修改系统音量。

## 构建与运行

置顶开启且窗口可见时，操作前台浏览器会让小窗临时退到其后，连续5秒无输入后恢复置顶，不抢焦点。仅在受支持浏览器位于前台时，每500毫秒读取一次系统最后输入时间戳和前台窗口；不读取按键、网页、URL或窗口标题，不安装键鼠钩子。时间戳包括鼠标移动；恢复精度受500毫秒检查间隔影响。支持Chrome、Edge、Firefox、Brave、Opera、Vivaldi进程，未识别的浏览器不启用此行为。

浏览器拖动同样按5秒闲置恢复；其他程序的顶层窗口移动/缩放结束约300毫秒恢复。小窗、设置和托盘操作排除；手动关闭图钉、隐藏或退出停止浏览器检查。只修改小窗层级，不改变窗口位置尺寸或暂停消息接收。异常遗漏拖动结束事件时，仅在让位期间每2秒检查一次窗口移动状态。

同批通知及两秒内密集通知合并声音；每条消息仍正常显示，不排队补响。阅读计时、闲置恢复和打开声音开关不触发旧消息重播。

要求 Windows x64、.NET 10 Windows Desktop Runtime、Node 22 或兼容版本；构建另需 .NET 10 SDK。

```powershell
npm ci --prefix bridge --ignore-scripts
npm test --prefix bridge
./scripts/build.ps1
# artifacts/app/FeishuMessageOverlay.exe
```

默认生成依赖已安装 .NET 和 Node 的轻量版，不携带它们的运行时。`-SelfContained` 可携带 .NET 运行时，Node 仍需安装。构建脚本仅在发行副本中移除未运行使用的 TypeScript 声明、备用 SDK ES 构建和类型包，保留运行依赖与许可证。程序不会静默安装软件。

当前是普通 EXE/ZIP，不使用 Windows 通知中心、MSIX、Windows SDK 或通知读取授权。源代码和发行包不含应用凭证、私有群配置或消息。

## 配置飞书

使用自己的企业自建应用，启用机器人，取得应用身份权限 `im:chat:read`、`im:message.group_msg.include_bot:read`，订阅应用身份事件 `im.message.receive_v1`，接收方式选择长连接。按租户要求审核发布，将机器人加入明确授权的目标群。手选模式保存独立群 ID 名单（配置界面最多五个），可进一步配置机器人发送者白名单。

开启并保存“自动监听本机器人已加入群”后，软件以官方核实的当前成员列表为接收范围，不受手选五群上限限制。新加入群自动纳入，退出群在成员列表刷新核实后停止。仅接收这些群内其他机器人的新消息，不监听私聊、普通成员聊天或本机器人未加入的群。成员列表约每分钟刷新，失败时清空接收范围并退避重试，不默认监听全部群。关闭自动模式恢复原手选名单；该开关重启后恢复。

右侧时间列固定为 UTC+8（北京时间），由消息时间戳转换，与 Windows 时区无关；悬停可看完整日期与 UTC+8 标记。正文里的时间原文不修改。滚动条采用4 DIP细滑块、12 DIP透明命中区，滚轮/拖动/键盘操作时显示，闲置淡出，不挤占正文宽度。

网页登录不等于 API 授权。外部群另有认证、对外共享和发布要求；仅在确需且获准时允许机器人加入外部群。现有机器人、尤其自定义 webhook 机器人是否可被接收，必须在目标群用自然新消息验收，不能仅凭连接成功承诺。

设置中提供官方扫码创建与受保护的本地凭证输入。已有应用不要重复创建。密钥通过私有标准输入管道交给 SDK，不作为命令行或环境变量传递。默认只用于当前会话；用户明确选择并提交后才使用当前 Windows 用户 DPAPI 加密保存。不要通过聊天发送密钥。

官方资料：[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive?lang=zh-CN)、[外部群机器人](https://open.feishu.cn/document/develop-robots/add-bot-to-external-group)。

## 可选：转发到本人微信 ClawBot

小窗默认不携带微信配置。由用户明确批准并亲自扫码后，可通过腾讯官方 `@tencent-weixin/openclaw-weixin` 与隔离 OpenClaw Gateway，将小窗真正接收且去重后的机器人新消息发送到唯一绑定的本人微信会话。电脑须保持开机、联网且不休眠。不会另建飞书长连接、读取历史、转发普通群成员聊天或附件，也不调用模型。

可选部署需 .NET 10 SDK，运行 `scripts/install-weixin-forwarder.ps1 -ApplicationDirectory <小窗发行目录>`；它安装独立固定版本 Node/OpenClaw/腾讯插件，不修改系统 PATH、不注册新服务、不导入现有 AI 凭证。官方扫码窗口由本人确认；先在微信机器人聊天发送 `/echo 测试123` 验证会话，再从小窗托盘开启“微信转发”。程序内部在本人专用 LocalAppData 目录保存 Gateway 令牌、官方微信绑定凭证和会话上下文；源码、发行 ZIP 不包含这些文件。官方 SDK 凭证文件依赖用户目录访问控制，并非本程序的飞书 DPAPI 文件。通道日志与引用/媒体缓存关闭，只处理本人固定虚构 echo，其他微信输入不进入模型或媒体下载路径。

启用转发后，标题、可读正文、时间与选定 HTTP(S) 链接会经过微信服务端，不能再描述为所有消息始终不离开本机。托盘开关可关闭转发；暂停/退出飞书小窗会清空待发队列。发送使用64条有界内存队列及2分钟新消息期限；只对本地网关明确未发送的忙状态有限重试，未知发送结果不重复补发。

微信正文使用空段落区分实际卡片文本行，时间为 UTC+8。隐藏“查看雷达”按钮及相同操作链接，保留一份完整“查看机会”Markdown链接，不改变查询参数或使用第三方短链。选择置顶群且当前内存已有该群最新消息时，每次普通推送上方附最新置顶1条，下方本次消息；置顶自身更新不重复两遍。置顶未收到、取消或退群时不编造、不拉历史；进程重启后仍等待新置顶消息。

按官方通道4000字符分段建议，长内容按段落/安全字符边界顺序编号发送，普通链接不拆分。超过单条长度的完整链接明确提示回电脑查看，不截断伪造可点击网址；分段发送失败不重复已发送段。微信客户端的 Markdown/链接策略及目标网站可达性仍需实际验证，API成功不等于用户已读或网站能打开。

可选 Gateway 安装约560 MiB，实际内存显著高于仅运行小窗；它不属于13 MiB级小窗发行目录，不应称为零资源成本。官方项目：[Tencent/openclaw-weixin](https://github.com/Tencent/openclaw-weixin)。

## 隐私与边界

先按群 ID、发送者类型及可选发送者 ID 筛选，再解析正文。窗口只显示正文与时间；内部 ID 用于过滤和去重，不在界面显示或常规日志中输出。只有普通消息的内存接收缓存受 100 条、30 分钟的保留上限约束，常规显示范围始终最多三条；独立置顶槽不受这些上限约束。每条正文最多 16,000 字符，过长或不支持内容有明确提示。卡片仅显示官方事件实际提供的可读文字，不保证附件或像素级还原。

选定的置顶群使用独立内存槽，上方最多固定显示最新一条，不占下方三条名额，也不重复进入普通轮播。收到后持续保留，下一条替换；普通队列到期、容量淘汰、轮播结束或清空不会移除此置顶槽。用户取消/切换置顶群或该群不再处于已核实授权范围时移除；从未收到过该群消息或进程重启后等待新消息，不伪造历史、不保存聊天正文。

暂停和清空按钮清空普通消息队列，不删除飞书或系统通知；暂停期间已授权的置顶最新消息保留。失去该群读取范围时停止并移除相关置顶展示，退出进程释放全部消息内存。重连使用新时间基线，避免历史重放。新消息只触发增量界面更新，普通区只创建当前最多三个消息容器。正常运行不定时写验收回执，不保存正文。偏好启动加载一次，用户修改后合并保存。配置凭证与群选择由明确配置动作保存。

诊断计数只在内存。明确执行 `FeishuMessageOverlay.exe --export-diagnostics <输出文件>` 才导出一次非正文状态、群计数和布局信息；导出文件含私有群 ID，不应提交源码。`--diagnose-saved <输出文件> bot-only` 仅用于已有合法配置的机器人元数据诊断。

## 验证

构建脚本运行核心检查、真实 WPF 窗口和私有桥接的无凭证合成检查，包括真实 DispatcherTimer 的 5 秒与 15 秒逐条推进。它不等于每个真实目标群已验收，也不证明物理音响已听见。具体范围见 [SOURCE-VALIDATION.md](SOURCE-VALIDATION.md)。Windows CI 使用无凭证测试，不连接私人群。


自动高度与字号拟合：按最终正文宽度、置顶一条＋普通三条的实际总高以及屏幕工作区高度，有限次缩小本次显示字号，优先同时显示完整正文。启动/归位可调整窗口高度；用户手动改变窗口尺寸后按该尺寸拟合。最多9次测量，保护下限10.5 DIP；只在当前显示消息、窗口尺寸、字体或设定字号变化时重算，不持续循环。设定字号与本次临时字号分开，临时缩小不覆盖用户保存的字号。达到下限仍放不下时，设置里的字号提示会说明需手动查看；不删正文，也不声称极端内容能可读地全放在一屏。

自动停留计时只推进到下一条普通消息，不在同一消息内部自动滚动或分段翻页。超出下限仍很长的正文保留手动滚动查看；用户可关闭自动停留或手动操作暂时暂停阅读。置顶最新消息保持独立，不参与轮动。

## 消息卡片

交互卡片按事件明确提供的标题、段落和按钮地址展示，不根据交易文案猜造标题或指标。提供了标题模板颜色时按该模板映射；事件丢失颜色/布局元数据时用紧凑中性样式，不能保证飞书客户端的像素级原貌。普通文本不强制套卡片标题栏。正文保留换行，支持基础Markdown加粗和HTTP(S)标签链接，复杂表格、图片、输入控件和回调行为不执行。

按钮只有在接口提供可用HTTP(S)地址时才能打开，参数保留；缺地址或非网页协议的按钮禁用，不从正文猜造目标。所有链接均需用户点击才打开默认浏览器，不自动访问。每条卡片不再追加附件/组件支持说明，边界在这里集中说明。卡片标题、正文、时间和按钮共同参与完整高度/字号测量，仍为独立置顶1条＋普通最多3条，字号下限10.5，不自动在同条消息内部翻页。

### 按钮地址与消息详情

支持接口明确提供的 `url`、`multi_url`、`open_url` 和 `behaviors` 中的网页地址，保留完整查询参数；不把回调值当作网址，也不把正文链接猜配给按钮。对于已核实群内刚收到的机器人卡片，软件可用已有应用权限查询该条准确消息 ID 的详情，不拉取历史列表。详情未提供目标时保留事件内容；请求失败或缺少权限时停止本会话的详情探测，不影响新消息接收，不自动申请权限。

部署者可按具体需要另行授权 `im:message:readonly`，用于查询已监听的新消息详情，不需要更广的 `im:message`。v24 样本曾因未解析事件内编码 JSON `user_dsl` 而丢失按钮地址和标题颜色；详情接口返回的是简化内容，未能补齐。v25 已在原事件内有限解码这个明确字段，恢复其提供的标题模板、正文和安全按钮目标；无需凭正文猜造按钮映射。不存在或无效的 DSL 保留简化内容。仍不承诺图片、复杂控件或所有来源均可原样还原。

显式单次字段形状诊断仅统计递归字段路径、类型、HTTP 目标数量及编码 JSON 数量，不输出字符串值、真实 URL 或原始响应；默认不启用，不持续写诊断文件。它帮助区分简化标签与嵌套地址，不执行回调或解析任意正文为操作指令。

## 进程生命周期与桌面部署

日常使用桌面快捷方式或已授权的当前用户自启。v28 桌面入口通过本机公开 Windows 进程创建接口启动应用；一次性隐藏启动器随即退出，应用不属于工具的 Windows Job。没有后台看门狗、服务或自动重启循环。历史一次退出的直接原因仍未证实；隔离测试证明 kill-on-close Job 能结束其成员，并证明本次独立启动的应用能在启动器结束后继续运行。

打包的开发工具可能将同名 AppData 路径重定向到自己的包缓存。同账号、同路径字符串不保证访问同一份配置。部署时可在发行目录放置 `storage-location.json`，其 `directory` 仅指定当前用户 AppData\Local 下既有的 FeishuMessageOverlay 私有目录。程序验证路径并复用原有设置、选择与 DPAPI 文件，不复制、解密输出或迁移凭证。该本机标记不属于源码或通用发行包；不得随源码上传。没有标记时使用正常 LocalAppData 目录。

已保存音源若使用上述逻辑目录，程序仅在原文件不存在时映射到同一既有应用私有目录中的相对文件；不搜索私人文件，不改变系统音量。原目录必须保留；清理或迁移开发工具缓存前应另行规划安全迁移，不能直接删除当前使用目录。桌面入口安装脚本为 `scripts/install-desktop-launcher.ps1`，只替换本应用的既有快捷方式，不修改系统安全配置。

本地 `lifecycle.jsonl` 只在启动、明确退出/会话结束及未处理异常时记录时间、PID、原因标签、Job成员状态和异常类型/最多4个本应用方法名；不记录异常消息、消息正文、群名/ID、URL、路径或凭证。文件限16KB，最多保留一份16KB前卷，无定时写盘或后台轮询，不将异常标为已处理来掩盖错误。外部强制结束不能保证写退出记录；下次启动的未闭合记录仅是线索，不能单凭它认定崩溃原因。这些本地记录不属于源码/发行归档。
## 微信专用字段精简与渠道边界
