# 飞书消息小窗

Windows WPF 桌面小窗，通过飞书官方 Node SDK 长连接接收指定群的机器人新消息。默认位于工作区右上角，支持置顶、拖动、边缘缩放、字体和字号、透明度及声音提醒。普通成员聊天默认不显示或提醒，发送者按官方身份字段筛选。

主界面与官方连接器已集成。模拟演示用于界面测试；真实群消息接收、免打扰场景及现有机器人告警源仍须完成实际验收。源码和发行包不包含任何部署者的应用凭证、群配置或消息。

## 运行与构建

已在 Windows 11 x64、.NET SDK 10.0.401、Node 22.20.0 环境完成本机构建与运行检查。其他系统版本和显示器配置需实际验证。

构建需 Microsoft .NET 10 SDK、Node 22 或更新兼容版本：

```powershell
npm ci --prefix bridge --ignore-scripts
npm test --prefix bridge
./scripts/build.ps1 -SelfContained
# 解压构建输出，运行 artifacts/app/FeishuMessageOverlay.exe
```

省略 `-SelfContained` 时，目标电脑需要 .NET 10 Windows Desktop Runtime。自包含包携带 .NET 运行时；两种包均包含桥接与官方 SDK 依赖，但不携带 Node 可执行文件，目标电脑仍需兼容 Node 运行时。程序不会静默安装运行时。

开发界面可用 `dotnet run --project src/Overlay.App` 启动；真实连接还需要构建脚本准备的桥接目录和依赖。CI 在 Windows 上构建并运行无凭证测试，发布 ZIP 构建产物；本机测试通过不代表远端 CI 或真实消息已通过。

当前发布形式是普通桌面 EXE/ZIP，不依赖 MSIX 身份、Windows SDK 或 Windows 通知监听授权。未签名程序可能显示系统提示，应遵守所在环境的安全策略。

## 配置自己的飞书应用

部署者需使用自己的企业自建应用，并完成适用的用户授权、租户审批和发布配置。网页登录只建立平台会话，不等于消息 API 权限。

当前接收路线需要机器人能力、应用身份权限 `im:chat:read` 与 `im:message.group_msg.include_bot:read`，以及应用身份事件 `im.message.receive_v1`，接收方式选择长连接。监听机器人需加入明确选择的群，软件配置一至五个准确 `oc_` 群 ID，可选设置 `ou_` 机器人发送者白名单。不能用普通群消息权限替代机器人消息权限来声称覆盖现有机器人。

外部群另需满足飞书的认证、对外共享和版本发布/审核要求。按实际用途设置允许机器人加入外部群，外部用户单聊只在明确需要并授权时开启。对外共享的权限适用范围和现有机器人、尤其自定义 webhook 机器人事件覆盖，必须用目标群实际新消息验证；可入群不等于已证明可接收全部机器人消息。

在设置面板使用“连接飞书”配置自己的应用，Secret 使用本机受保护输入。“扫码创建应用”调用官方注册流程，由用户在官方页面确认实际权限；已有应用无需重复创建。凭证通过私有进程管道交给本机 SDK，不使用命令行参数或环境变量传递。默认只用于当前会话；用户显式勾选并提交保存后，使用当前 Windows 用户 DPAPI 加密保存应用凭证。“已有扫码应用”可由用户主动加载这份本地配置。

软件提供未连接、连接中、已连接、重连、错误和暂停状态。长连接建立只表示传输已就绪，不能证明群权限、事件订阅或特定告警源已验收。

官方参考：[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive?lang=zh-CN)、[外部群机器人要求](https://open.feishu.cn/document/develop-robots/add-bot-to-external-group)、[权限说明](https://open.feishu.cn/document/server-docs/application-scope/introduction)。

## 托盘与外观

主窗口不占主任务栏按钮。X 隐藏到右下角系统托盘，已建立的监听和声音继续；托盘提供显示/隐藏、置顶、设置、恢复不透明及明确退出。退出停止桥接、清空消息并释放托盘图标。同一 Windows 用户重复启动会恢复已有窗口。

开机自动启动开关默认关闭；只在用户点击开关时注册或撤销本软件的当前用户自启项，设置失败回滚。开启后启动时隐藏到托盘，不会因此取得新的读取授权；当前实现仍需用户完成连接配置。

设置位于独立、不透明的小面板。透明度范围 60–100%，默认96%，即时预览并保存，窗口文字也会一起变淡；托盘可恢复不透明状态。置顶、窗口尺寸、字体、字号、透明度和声音偏好保存在本机。

声音只有开关，跟随系统音量，无独立音量滑块。支持导入本人有权使用的本地 WAV/MP3（最多2MB）；仅引用本机文件，不上传或加入源码归档。发行包没有附带或声称提供 Apple 官方 Rebound 音频。视觉布局参考 Twinkle Tray 的紧凑桌面面板。

## 隐私与显示边界

群 ID、群类型、机器人发送者身份和消息时间检查在正文解析前完成。普通成员消息不进入显示或提醒流程。当前发送者主要显示机器人 ID；未额外申请通讯录权限补全名称。

消息只留在内存，最多100条、30分钟，每条最多16000字符，截断会明确标记。软件不保存消息正文、不写正文日志、不把消息提交 GitHub 或发送到第三方服务。与飞书的网络通信限于官方认证、必要元数据和已授权消息接收。

去重记录受时间与容量限制；过期清理允许持续运行，容量保护或队列拥堵会显示可恢复停止状态。启动、清空及恢复建立新基线，避免重播旧告警；暂停、失权/错误和退出清空本软件内存消息。清空操作不删除飞书或系统通知。

卡片显示官方事件转换后实际可读取的标题和文本，并标注不支持内容；不保证完整原始 JSON、附件或像素镜像。不会通过客户端 token、cookie、内部数据库、注入进程或绕过企业限制补齐数据。

## 验证与安全诊断

已完成本机构建、20项核心检查、8项 Node 过滤检查、25项无凭证诊断契约检查，以及 WPF 模拟/桥接/生命周期运行检查。详细通过范围和未验证项目见 [SOURCE-VALIDATION.md](SOURCE-VALIDATION.md)。

诊断入口：`FeishuMessageOverlay.exe --diagnose-saved <结果文件> bot-only`。程序内部加载用户已批准保存的 DPAPI 配置，只查询机器人名称、应用 ID 和启用状态；白名单结果不含凭证、群或消息。未配置时明确失败，不注册新应用或改变权限。

真实验收应使用目标群现有机器人的自然新消息，检查发送者身份、可读正文、声音、去重、暂停和恢复；不能把监听机器人自行发送或模拟消息当作现有告警源验收。
