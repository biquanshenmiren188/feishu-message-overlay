# 关机后持续接收：只读评估，尚未部署

当前v33链路仍需要Windows接收程序运行。网站页面及签名接收服务不会自行登录飞书；关闭电脑后不会有新的群消息。

## 实测资源

2026-10-02只读短样本：服务器2核，物理内存1613MiB，可用758–764MiB，无swap。已有Python3.12.3/OpenSSL3.0.13，没有Node/npm。新增网页签名接收进程约12MiB、1任务。原站相关服务均active。

一次1秒CPU约59.9%；随后三个2秒样本为87.7%、73.3%、44.5%。短样本反映较大波动，不能据此得出长期负载、泄漏或必须升配结论。内存暂有空间；云接收候选应先限制资源并实测，不能承诺对原业务零影响。未查看购买页、升配、安装运行时或修改云端凭证。

## 最少变动方案

优先复用本项目官方Node SDK及已有bot过滤、去重、群发现和卡片DSL兼容逻辑，用独立轻量适配器产生网站统一消息结构；不安装OpenClaw、不搬WPF/.NET桌面界面、不增加第二套业务网站。当前C#正文/卡片提取仍需移植成小型JS模块并以既有合成卡片对照验证，不能把“bridge可运行”等同完整解析已经迁移。

新增官方Node运行时/锁定SDK依赖属于待批准的服务器安装。内存预算初步按128–192MiB、CPU小比例限额规划，仅为候选预算而非Linux实测结果；复用当前Python快照层与nginx路径。可用同服务私有管道传递标准化消息，不公开新的无签名入口，不复制Windows发布私钥。生产日志仅状态/计数，正文仅保留用户已批准公开的有界快照。

飞书官方明确同一App多个长连接是集群分发，不广播，随机一个客户端收到事件。因此云端必须成为唯一飞书接收端。桌面改为读取同一云端数据源；云端失联时桌面显示离线，不自动偷开本地飞书长连接。设置/置顶选择若需更改云端公共状态，使用认证控制通道，不能让匿名网页访问者写配置；阅读秒数仍各客户端独立，除非另行要求同步。

## 切换与回滚

1. 无凭证完成解析/去重/启动基线/离线状态/桌面读取候选测试。
2. 获具体许可并由用户在受保护界面亲自输入App Secret；通过受保护传输送入服务器专用低权限服务凭证存储，不经过模型、命令行、日志或聊天。不得解密迁移现有Windows DPAPI文件。
3. 先将桌面切为云读取模式并确认本地飞书连接关闭、重启不会重开，再启动唯一云接收。保留群筛选和pin配置，实际等待自然消息验收。不以双端并行试运行规避切换。
4. 回滚先停止并确认云接收退出，再恢复桌面本地接收与当前签名发布。禁止云/本地同时主动重连。切换可能存在短暂接收空窗，未获历史回补授权时不能承诺绝不漏过该时段消息。

云端使用systemd有限重启和退避；群发现失败收紧接收范围，消息ID有界持久去重，防止服务恢复后旧事件再次响铃；事件处理先在官方3秒期限内确认，再执行有界解析工作。正式实施前需检验现有卡片详情异步调用对确认时间的影响。

## 需要的明确批准与唯一敏感操作

允许在现有服务器安装官方Node/SDK、运行唯一低权限飞书接收服务、持久保存该App凭证，并把桌面切为读取云端消息。仍只接收本机器人已加入群内其他机器人的消息，不新增私聊/发送/历史权限，不扩大原站业务范围。用户本人在专用安全输入窗口输入并确认上传App Secret；不需要把密钥发到聊天，也不要求代理读取本机保存的秘密。

升配不是本轮默认前提。如候选测试显示CPU长期饱和或内存不足，再核实实际可购规格、价格/续费和是否需停机，供用户单独决定；本轮没有购买或升配授权。
