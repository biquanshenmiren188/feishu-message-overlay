# 报警断流显示与切源验收（2026-11-13）

## 取证与原因

用户截图为 Binance BTC/USDT 显示「行情中断」，但未显示备用。调查时两条现有规则均为 auto，且各有四个合格备用；这一当前状态本身不是问题已解决的证据。

在名称为「3号」的 Chrome 中只给代理验收标签页模拟 4 秒响应延迟，抓到同一请求的后台 status=watching、source=Binance future，而页面显示 Binance「行情中断」、价格为 —。该复现未改变生产行情或用户规则。响应记录保存在任务 work/routing-browser-before.json。后台连续 45 秒只读采样：Binance 样本年龄 3.321–10.359 秒，全部 watching；电脑时钟比服务器约快 1.162 秒。

旧网页用 Date.now() 减去交易所 sampleAt，超过 12 秒便自行把后台状态覆盖成 stale；紧凑状态接口不带 serverTime，网页又每 10 秒才刷新。设备时差、网络传输延迟和浏览器旧快照会导致网页早于后台认定断流，因此页面以为应切备用，但后台仍在使用合格主源。本次明确复现了与用户截图一致的状态矛盾；原截图时刻没有完整切源日志，不能声称还原了那个历史请求的每个细节。

## 修复

- 后台切源与触发判断继续执行严格 12 秒行情新鲜度、精确身份、预检查资格和指定备用范围；不通过放宽过期时间或忽略失败来消除告警。
- 网页直接采用后台报警状态，设备时间不再生成交易所断流状态。紧凑接口补 serverTime，价格展示使用服务器时间及 performance.now() 单调耗时；延迟/旧快照隐藏过期价格，不冒充实时价格。
- 网页同步间隔由 10 秒改为 2 秒，仅可见页刷新。网页 API 失败用原有状态位置提示页面更新失败，和交易所断流区分；恢复后清除。样式和布局无改动。
- 每条规则在运行状态中保留最近 12 次路由变化，包含时间、实际来源及原因（主源正常、使用备用、备用关闭、身份不合格、备用未完成验证或没有新鲜备用）。不改用户阈值、频率、交易所选择、设备或推送设置。

## 模拟验收

86 项 Python 和 12 项 JS 用例通过。新增真实 Market.poll → Store.tick → 事件队列的隔离超时模拟，六主交易所 × BTC/ETH/SOL 共 18 组均在主源超时、旧价超过 12 秒后选择其他交易所现货，事件实际来源与选中来源一致。无真实推送。

同时覆盖：首个备用也超时则换下一家、全部超时暂停且不制造报警、主源三个不同有效更新后切回、不突破 30 秒提醒间隔、指定备用失败不私换第三家、关闭备用时不切换；记录对应路由变化。旧行情年龄未超过 12 秒时继续主源，符合已定义策略。

3号浏览器运行真实 Store/API/候选网页的 loopback 隔离环境，逐步确认：主源正常 → OKX 现货备用 → Bybit 现货备用 → 主源持续恢复后切回 → 全部断流显示中断/— → 延迟响应不再误报断流 → 网页 API 失败明确提示更新失败 → 恢复显示备用。手动冻结恢复样本超过 12 秒时恢复计数会重置；持续提供三个新鲜样本才切回，符合防抖要求。393px 手机视口无横溢，原 CSS 和布局不变；不是实体 iPhone 测试。
