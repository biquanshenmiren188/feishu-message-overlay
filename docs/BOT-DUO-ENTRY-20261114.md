# BOT 大屏右侧紧凑卡片与进入定位

用户确认 B 方案：大屏卡片放右侧，普通手机放消息下方；Duo 卡片进一步压缩。其余页面、推送规则、设备绑定和报警后端不变。

## 行为

- 720–1199 CSS px：消息与卡片左右排列，右侧单列独立滚动，高度跟随消息面板。压缩卡片留白、指标与充提表间距，保留所有数据、警告和操作。
- 719 px 以下：继续上下排列；1200 px 以上保持既有桌面卡片布局。
- 1199 px 以下按普通消息实际行高计算消息区，容纳至少六条；置顶仍独立保留五条，一次展示一条。
- 第一次有效消息渲染、返回页面时定位最新。用户主动阅读历史优先，后续到达继续既有定时阅读逻辑。

## 原因和修复

旧实现收到第一批数据就消耗初始定位标记；延迟布局触发的 scroll 又会被当成手动阅读，导致双帧定位取消，之后只能逐批推进。

新增独立定位控制器：等到内容和面板可用后准备阅读游标，布局完成再提交到底部。隐藏、忙碌状态保留待定位状态；真实手势取消待定位。普通布局 scroll 不再自动进入手动阅读。尺寸变化只在跟随末尾时继续跟随。

## 验收

- Node 71 项通过：定位、定时阅读、六条高度、移动端阅读位置保护、置顶历史。
- 三号 Chrome 候选隔离页：393、719、720、768、820、1100、1440 px；窄屏上下、大屏左右，最新消息到底部误差小于 1 px，移动宽度完整六条普通消息。
- 820 px 紧凑卡片约 288 px 高（同样数据初版约 328 px）；卡片内部无横向溢出。1100 px 约 259 px。
- 手动 Home 阅读旧消息会暂停自动推进；重新加载、离开后返回都回到最新。
- 原生产资源图、合成 API 的九组连续更新通过：新消息、30 条裁剪、置顶更新、上方卡片增高、消息屏蔽回流、卡片屏蔽回流、内部滚动与规则刷新、规则 503 清空恢复、触摸活跃期间 503 恢复。目标卡片视觉位移最大 0.31 px，业务 JS 无异常。扩展自身异常单独排除。
- 验收工具为 Chrome 尺寸模拟，不代表实体 iPhone/Safari 已实测；没有发送手机通知。

## 发布方式

从已核验线上版本克隆，新增哈希定位模块、样式、定点补丁后的 BOT 主模块，仅替换 BOT 入口；独立 PWA fallback 同步引用。其余静态文件与链接逐一校验，唯一动态缓存例外为 market-display-cache.json。

部署锁内检查基线与 fallback，发布前后核对报警配置、设备绑定、订阅、后端文件和进程 PID；任何不一致中止，失败仅在仍拥有 current 时回滚。提交及发布标识另行补充。
