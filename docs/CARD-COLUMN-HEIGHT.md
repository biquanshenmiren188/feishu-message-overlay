# 卡片先填满一列（2026-10-18）

桌面摘要上线后右侧消息变短，`MeasureContentHeight` 仍只依据右侧文字设置整个窗口高度，导致左侧卡片在屏幕尚有空间时提前分到下一列。原有逐列排布顺序没有改变，错误在共享窗口的高度预算。

现在布局面板测量所有卡片单列所需的真实总高，合并进自动窗口高度：先向下扩到内容所需高度，最多到屏幕工作区下边界，再沿用从右向左的逐列排布。卡片内容/数量变化会触发一次合并布局；只调整右侧摘要不会缩掉左侧容量。用户主动手动缩放时仍尊重窗口高度；屏幕宽度不足时保留滚动，卡片不丢失。右侧摘要、动作按钮与配置不改。

独立WPF布局专项增加三张卡片配空短消息、十二张卡片铺满屏幕后换列、减少卡片回到单列的真实布局断言；原有机会卡片专项保持不变。

验证：独立 `--card-column-height-contract` 六项WPF布局断言通过。实际1392 DIP工作区中，3张卡片总高735、窗口737.33、1列；12张总高2940、窗口1392、3列；减少至3张回到1列。手动400高仍保留。完整机会专项两次在既有系统剪贴板读回断言失败（不同用例），未进入布局阶段；未修改复制逻辑或放宽该测试，改用不接触剪贴板的独立布局专项，不能宣称完整机会专项通过。
