# 网页推送屏蔽与完整链路回归

用户保存了 UNITREE 三端屏蔽，BOT 普通列表和置顶强信号仍展示。现场只读核对确认规则已保存，服务端对源中的 14 条普通消息和 1 条置顶消息均判定隐藏；网页此前直接展示公共 feed，没有应用消息规则。

## 修复

- 新增按推送码认证的只读 `message-decisions`，复用电脑消息规则，覆盖普通、历史、置顶和多组合；不写拦截历史、心跳或手机订阅。
- 浏览器对消息 ID、标题、正文、时间计算指纹，只展示对应码已验证的内容。隐藏移除，静音保留且不响；同 ID 内容变化、换码、保存规则、失效和请求失败均撤销旧许可。未绑定仍全部显示。恢复历史消息不重新响铃。
- 已屏蔽入口增加“网页当前”，可查当前隐藏的普通和置顶消息；“电脑历史”“手机历史”保持独立。打开后冻结列表，用户点击刷新才更新。
- 明确的强信号格式损坏时保留 invalidSignal 标记，不能因为解析成空组合而绕过已配置筛选；默认全部接收及普通公告不受影响。
- 保存成功广播不含身份或规则内容的失效通知，其他已打开页面重新校验；保存失败不广播。

## 验证与发布方式

- 后端完整 154 项检查通过；前端原有 238 项及设置加载器修正后的 23 项分别通过，合计 261 项已验证。
- 新策略状态测试、普通/置顶、静音声音、同 ID 变更、切码竞态、401/过期、历史入口和零写入检查通过。
- 最终产物另用 Chromium/WebKit × 1440/393/320 px 加载真实候选 HTML、生产增量 bundle 和 PWA 入口。校验源文件不代替校验产物：首轮发现赋值左值别名遗漏，在部署前修正。
- 验收保留双边 OI（50 万 USDT 门槛）、卡片管理、GC 纯 JSON、已屏蔽卡片入口、手机触摸时立即撤销隐藏消息及不横向溢出。
- 增量发布以线上 `20261028-card-oi-1793159424` 为基线，保留未合并的卡片/历史预览功能和其他生产叠加；只替换列明文件，不能完整重建覆盖。
- 发布前固定源提交、全量文件哈希、浏览器报告及服务端隔离测试。guard 内检查基线、设置/绑定和其他服务 PID，只重启 `radar-webpush-test`；失败回滚代码，不回滚用户后来保存的数据。

本次不构建或发布 Windows 安装包，模拟 WebKit 手机视口不等于实体 iPhone 锁屏通知验收。生产只读核验，不发送测试消息、不改用户规则。
