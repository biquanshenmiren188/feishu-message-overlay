# 推送中心与统一导航

用户确认交互预览后实施。入口 `/radar/robot-push/center/`，安装版 `/radar/push-test/center/`。BOT、消息设置、报警设置右上角打开快捷管理，再进入完整中心；其他原页面没有推送码按钮。BOT 显示「已连接推送码」，设置页显示「推送码已绑定」。完整码直接展示、复制，切换输入也不掩码。

中心提供码名称、新建并连接、切换、桌面连接状态与说明、PWA 通知管理、Bark 绑定/解除/手动测试及中心操作记录。没有桌面测试发送协议，因此使用真实心跳和连接说明，不显示模拟在线/测试成功。PWA/Bark 设备状态查询失败显示暂不可用，不冒充未绑定。

## 服务边界

独立 `radar-push-center` 服务（回环 18887），API `/radar/push-center-api/`。SQLite 位于 `/var/lib/radar-push-center/center.sqlite3`，只保存稳定 profileId 对应的名称、版本和中心操作记录。旧身份注册表继续作为配对、创建、令牌、订阅的权威来源；中心通过白名单适配接口使用它，避免复制身份或迁移旧凭据。旧 PWA、桌面规则、报警数据库/密钥与设备位置都保持。

名字写入有版本冲突校验和请求编号幂等；Bark 写入沿用报警服务的版本和幂等协议。浏览器遇到不确定结果保留原请求供重试，切码后丢弃旧响应。新码创建沿用原会话请求编号，避免网络失败重复生成。手机端切码仍走已验证的订阅转移、恢复日志和 worker 配置流程。

中心不存 token、完整推送码、订阅 endpoint 或 Bark Key。码仅鉴权后按请求展示，所有 API 禁止缓存，访问日志关闭。Bark Key 只通过 HTTPS 提交，原报警服务负责加密保存。测试通知须用户点击并确认，检查中使用隔离假数据，不主动发送真实通知。

## 导航与发布

七项顺序：全市场费率、机会筛选、充提查询、HY限额查询、BOT、消息设置、报警设置。启动壳和静态页面直接输出最终导航，head 同步加载 `navigation-stable.css`；选中态、未选中态宽度和字号一致，手机保留两行，避免后加导航和样式导致闪动。

`prepare-push-center.py` 从真实 current HTML 定点补丁生成候选，保留其他线上覆盖；`seal-push-center.py` 固定基线/新文件和提交；`deploy-push-center.py` 在发布锁内核验并克隆 current，只增加独立服务及路由，不重启旧消息/报警服务。失败恢复静态链接和 nginx，不恢复用户数据。PWA 增加 center 符号链接，原 manifest/worker/订阅身份不变。

## 验证

10 项中心 API/存储测试覆盖旧码、隔离、持久化、并发版本、重复请求、错误来源、鉴权、设备故障和代理白名单。35 项原身份/导航检查、35 项报警后端检查通过。中心和报警合成浏览器分别覆盖 1440/393/320px，验证改名、码切换、旧响应隔离、Bark 绑定及原请求重试；旧规则未覆盖。部署及正式站记录在验收完成后补充。
