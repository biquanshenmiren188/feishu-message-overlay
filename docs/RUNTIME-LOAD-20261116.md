# 2026-11-16 请求与后台计算优化

- 置顶历史已经包含当前消息时不再立即重复请求；同一 ID 正文更改、身份切换、规则保存仍刷新。
- 复用最多 128 条消息内容的纯解析结果；每次仍校验时间窗口和来源，按调用返回独立结果，跨方案的规则与 OI 富化互不污染。
- Live.tick 只比较可能变化的状态字段，避免每轮序列化整份状态两次；保留持久化与发送顺序。
- 行情快照按更新批次复用，并按交易所、精确基础币和审定资产身份索引备用源。资格、新鲜度、歧义、多倍率换算、切源和恢复条件仍调用原判断。
- 报警 CPUQuota 从 35% 改为 100%（最多一个逻辑核心），MemoryMax 仍为 256 MiB，不改行情轮询周期或 30 秒提醒间隔。

本分支先合入已部署维护基线 fix/pin-history-20261112，以保留 Bark 多设备、自定义正文、模板预览和备用源已有逻辑，不表示授权合并 PR。

验证：Windows 与生产 Linux Python 环境均通过 119 项报警测试、185 项推送测试；置顶历史 6 项 Node 测试通过。报警全套还强制走新索引重复检查。所有通知传输均隔离模拟，不向真实手机发送验收通知。

微基准（本机合成 6,005 条行情）：备用源 select 平均 13.57 ms → 0.036 ms，索引构建 3.78 ms/批次。重复消息解析 0.0071 ms → 0.0020 ms。仅代表局部计算，不代表整个服务器 CPU 同比例降低。

发布脚本在持锁与哈希基线校验下克隆现行静态和报警版本，只更新明确模块，保留配置/订阅/设备/规则并校验摘要；故障自动回退代码和本次 CPU 配额。只重启改动 Python 代码的报警、规则服务，机器人接收服务保持原 PID。发布与实测结果另补。
