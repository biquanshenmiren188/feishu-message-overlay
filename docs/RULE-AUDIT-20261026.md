## 已修复问题

1. **ASTER OI 路由缺失**：统一 relay 不支持 ASTER；前轮已改读主站 market-stats.asterOI，详见 ASTER-OI-FILTER-20261026.md。
2. **Hyperliquid OI 路由缺失**：同样请求不支持的 relay。现读取已有 gateway 的原生合约，精确核对合约符号，保留 k/数字前缀；命名空间/HIP-3 或计价未知不借用同名币数据。原生 USDT 不换汇；HYPE/PURR 原生 USDC 依据新鲜汇率换成 USDT，不重复翻倍。原生 OI 最长120秒、USDC汇率30秒，通过 expiresAt 继续限制共享缓存内数据。
3. **中文币种漏解析**：旧正则只接受 ASCII，手机漏掉中文信号；桌面 fallback 又把它当无R消息，跳过等级和最低百分比。现普通/聚集消息共享 Unicode 32字符及完整命名空间解析。
4. **旧消息屏蔽自动失效**：桌面曾沿用手机30分钟解析窗口，仍保留在30条历史中的消息超时后 rows=[]，绕过屏蔽。现分离展示历史解析和手机发送新鲜度；手机30分钟解析及既有更短发送/去重窗口不放宽、不补发历史。
5. **真实专题/DEX格式绕过过滤**：原测试仅覆盖假定标题格式。现按实际编号、多空路线解析专题与P优先级消息，执行币种、所、方向及OI；P/take 不冒充R。多组任一匹配沿用整消息隐藏语义。已识别普通/legacy交易信号损坏时仅已配置筛选的方案保护性处理，默认全部接收不变；这不保证识别所有未来未知格式。
6. **手机切码被线上版本号挡住**：设置页严格等于 radar-delivery-v6，但正式worker为 radar-delivery-v6-20261019-startup1。现兼容受控日期/构建后缀，仍拒绝v5/v7/异常版本；迁移恢复使用原请求。设备诊断保留具体v6构建号，不再错误记unknown；v5声明式兼容分支不变。
7. **多方案重复OI缓存和线程爆发**：旧嵌套池隔离模型中4个方案×7所产生28个读取、进程33个线程；服务TasksMax为16。按线上六所条目数构造的30份缓存净约84.82MiB，线上服务观察125/128MiB、memory.events max=11，未观察OOM。现仅共享公共数据、每所合并并发请求，全局最多3个OI读取线程；每次判定跟随共享代次，不用本地读取时间延长TTL；各consumer仅保留本次币对。规则、鉴权、判定和队列不共享。HTTP服务本身仍可创建请求线程，不能声称整个服务永远不超过16线程。
8. **断开的HTTP客户端触发二次错误回复**：近24小时295次断连各打印两份BrokenPipeError。回复阶段现在仅捕获明确socket断开并关闭连接，不再次回复、不重跑已提交操作，其他错误仍抛出。
9. **强聚集V2收益行漏解析**：正式消息的每条路线下一行已增加 `V2收敛 · 180秒 ·` 前缀，后端和网页却只接受行首净均。补齐该受限前缀，仍校验逐组净均、组数、方向和手机时效；旧格式与新格式身份/去重相同。真实当前feed只读回算从30/31恢复31/31，聚集消息从0恢复全部6组；未知版本/窗口不猜测接受。
