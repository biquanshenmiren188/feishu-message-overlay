# Bark 多设备绑定（2026-11-14）

一个推送码可绑定多个 Bark 接收设备。设备管理内直接显示完整 Key，可复制、添加、编辑、单独解绑、单独测试或测试全部。只修改设备管理弹窗和设备数量摘要；其他页面布局、报警编辑器、行情路由和用户规则保持原状。

## 数据和发送

- 单设备表事务迁移为带稳定设备 ID 的列表；原 profile、fingerprint、加密 secret 和 label 原样复制。原规则和推送码不变。
- 完整 Key 仅通过当前推送码鉴权的 `/devices` 接口按需返回，响应 no-store；不进入页面快照、普通 state、报警历史或部署日志。关闭管理/切换推送码清空内存列表。
- 添加不替换旧设备；重复绑定报错。编辑或解绑只取消该设备旧 Key 的未发送队列，其他设备不受影响。同 Key 改名不取消通知。
- 每次规则触发为各设备创建独立事件，8 个发送工作线程隔离单台超时。一个轮次共享 roundId，每台保留独立发送时间；持续满足条件时每台间隔至少 30 秒。迟到设备不会推迟健康设备的下一轮，也不会提前补发。
- Bark 参数仍为 critical、volume=5、call=1。未知发送结果不盲目重试。单次报警的部分发送失败不让已发送设备重复收到。
- 仍只使用用户勾选且已验证的现货备用源；身份和倍率换算、发送前新鲜度/阈值校验保持原有逻辑。

## 验收

- 108 项 Python 测试通过，含迁移/重启、双设备隔离、三设备 0/30/60 秒发送、单台超时、并发领取去重、迟到节奏、单次报警部分发送、鉴权隔离。
- 272 组倍率币发送场景扩展为每组两台设备；原六所普通币回归保留。19 项前端行情显示/币种匹配/备用源权限测试通过。
- 3号 Chrome 隔离页面：桌面新增、编辑、测试全部；手机 393×852 新增/编辑/保存、单设备测试；320×720 刷新保留四台测试设备，长 Key 自动换行，无水平溢出。生产规则未作为测试数据修改。
- 测试 HTTP 边界模拟 Bark 接受/超时，不能等同于实体手机收到或响铃。本轮没有向真实手机发送测试消息。

## 发布和回退

`scripts/deploy-bark-devices.py` 在私有生产数据库副本演练迁移，核对配置摘要；克隆当前静态 release，仅覆盖报警目录五个文件。只重启报警服务，其他服务和静态文件做哈希/PID 保全检查。

部署前保留权限 0600 的数据库备份；自动回退使用当前设备行反向转换，不恢复旧数据库覆盖新用户数据。若上线后已有一个推送码绑定多台设备，禁止回退旧单设备后台，保留新后台并修复；不能直接切旧代码。前端可独立回退，后台数据保留。
