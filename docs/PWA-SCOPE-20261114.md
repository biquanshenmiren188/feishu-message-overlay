# 桌面雷达导航范围修复

用户从桌面雷达图标进入，大屏右侧出现包含关闭、分享等按钮的浏览器栏。核验生产 manifest 后发现：id/start_url/scope 均为 `/radar/push-test/`，但 BOT、设置、报警、行情等导航跳到 `/radar/robot-push/` 等范围外路径。旧入口 nginx 使用内部 rewrite 展示 BOT，本身不会改变地址；用户点击正常导航后才离开登记范围。

这属于已确认的配置缺陷，与截图的范围外浏览器界面相符。没有实体 iPhone 远程调试，不能声称已经证明该设备侧栏消失。

修复仅将 manifest 的 navigation scope 改为 `/radar/`。保留原 id、start_url、名称、图标、standalone、manifest URL；服务 worker 与其注册范围、缓存和推送订阅不改。scope 是应用导航范围，不是扩大 service worker 控制范围。

Apple 说明范围外链接会打开浏览器：https://developer.apple.com/videos/play/wwdc2023/10120/ 。Manifest scope 定义：https://www.w3.org/TR/appmanifest/ 。

测试：既有安装身份不变、七个导航及推送中心均在新范围、其他域和无关路径仍在范围外，共三项通过。部署从线上原始字节只替换 scope，禁止用仓库旧 manifest 整份覆盖线上图标版本。发布锁保护；前后核对静态资源、fallback、worker、后端、规则、设备、订阅和服务 PID。

已安装 iOS 桌面入口何时采用新 manifest 由系统决定。先完全退出后重新打开验证，不要求删除图标、重新安装、清除数据或重新绑定。

## 同次线上验收发现的 manifest 鉴权故障

三号 Chrome 的 manifest 请求实际 302 到 Cloudflare Access 登录页，随后 CORS MissingAllowOriginHeader，Page.getAppManifest 得到空配置。已登录的 HTML 请求正常，但 manifest link 缺少 crossorigin="use-credentials"。按标准，即使同源，需鉴权 manifest 也必须设置此属性：https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/crossorigin 。

对线上六个现有 HTML 的同源 manifest 链接定点添加该属性，同时更新独立 fallback。原 URL、登录保护、Cookie、manifest、worker、正文脚本和样式均不改；不把 manifest 改成匿名可访问，不更改 Access 规则。

源码同步六个入口及旧入口部署模板，补充全部入口的凭据属性检查。三号浏览器复验必须以实际 manifest 成功响应与解析后的 /radar/ 范围为准，不能只检查服务器 JSON。
