# 手机 BOT 连续历史滚动（2026-10-17）

用户在 iPhone 中无法滑动机器人消息，只能点“到最新”。旧布局仅挂载五条消息，边缘翻页依赖 touchmove/touchend 的累计距离；手机历史轨道仅作进度提示，不能拖动。没有真实滚动范围的批次边缘不应承担手机历史导航。

手机宽度 ≤640px 时，将已接收的有界历史（最多100条，沿用原接收保留规则）放在同一个原生 overflow 滚动区域，取消触摸边缘合成翻页与手机 wheel 拦截。首次打开和“到最新”定位末尾，手动滚动仍暂停自动推进10秒，自动推进时滚到新接纳消息。新批次保留可见消息锚点；触摸与惯性期间仍由现有 gate 延后结构更新。电脑维持原分页阅读，全文保留、返回恢复位置。

`prepare_native_history.mjs` 仅接受已审计的 `d246d82e…` 线上bundle SHA，以AST从源码映射指定函数并替换三处已核对事件处理片段，保留摘要、盘口差、复制、滚动稳定等现有补丁。映射用于本次增量交付，其他bundle必须重新审计。使用 `deploy_summary.py` 校验基线、备份、同步PWA fallback并持锁原子切换，不重启消息服务。`board.dataset.version`为`native-history-20261017`。

验证：130项网页测试通过。Chrome393×852、100条合成消息、CDP真实触摸事件：指针下滑scrollTop从5868降至5644，反向上滑回到5868，页面scrollY仍为0，无误开全文；静止时全文打开/返回位置相同，Home可到第一条、到最新回到底部。这是浏览器触摸仿真，不是实体iPhone验收。此前检查过程一次截图定位受到自动播放影响，最终图片与测试以固定位置为准。

用户截图同时含旧“机器人消息/价格最大延迟45s”摘要，而服务器当前入口已是新版，说明截图中的页面未使用当前摘要；不能只凭截图断定缓存层。发布后需让已打开的页面重新加载一次新入口，不能以该截图推断最新解析规则已回归。
