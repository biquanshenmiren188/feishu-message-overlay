# 手机 BOT 阅读位置再次跳动

用户停在下方行情卡片阅读时，新消息到达或卡片更新后页面仍会回到上方机器人推送区。本次沿用原 UI、60svh 消息面板、240ms 原生触摸安静期和既有消息/卡片规则。

## 原因与修改

- 旧门控把消息框内部程序滚动也当成用户手势，关闭了卡片位置保护；而屏蔽、过期删除仍在门控期间执行。现在只有真实输入开启门控，只有对应滚动容器的惯性延长它。
- 手势期间需要隐藏的卡片立即移除内容和交互，只留等高无内容占位；安静后统一清理。状态文字、数量和规则摘要等可能改变高度的更新一并延后提交，规则本身即时生效。
- 卡片完整同步提交临时保留板块高度，避免替换节点的中间状态让浏览器压缩整页滚动范围。消息接受/规则过滤、列表渲染和尺寸计算也纳入同一个可重入事务，最外层按同 pair/ID 的可见卡片保持位置。
- 规则短暂不可用导致全卡清空时，只保留尺寸与锚点，最多 3500ms，不保留内容、不续期；下一轮有效规则恢复后释放。用户新输入、视口变化或页面可见性变化会取消旧位置恢复。长期失败仍展示原来的等待状态。

## 验证方法

实际基线为 `20261101-ss-book-cache-1793505553745329896`，BOT 使用 `performance-20261017/bot-feed-filter-8558edfdc4f12595.js`，其中包含 PR #56 的正式规则过滤逻辑。候选只替换四个目标函数与滚动 helper 导入，保留其他 186 个声明及所有非目标 bundle 字节；BOT/PWA 两入口仅替换新 bundle 地址。

`scripts/mobile-reading-fixture/` 使用真实生产静态图与本地合成 API，禁止访问外部数据、发送通知或修改真实推送码。通过页面按钮运行新消息、历史截断、置顶变化、卡片替换/排序、规则失败/恢复等场景，逐帧记录卡片位置、整页位置和高度。规则不可用时应没有原卡片内容，因此单独检查其缺失期间的整页位置，不能把这段帧丢掉。

旧版在 393×852 Chrome 回放中，全卡规则失败导致页面高度下降 2238px；即便最后恢复原位置，中间仍存在明显回跳。此证据来自浏览器隔离回放，不是实体 iPhone 验收。

## 发布约束

发布脚本先核对真实 release、3500 个文件的完整清单、BOT/PWA 所有静态依赖及独立 PWA fallback；只增量添加带 hash 的 bundle/helper，并替换两个 HTML 引用。保留 SS、组合图、缓存、复制及所有线上叠加。静态发布不重启服务或桌面程序，不修改推送规则、绑定或订阅，也不发送真实测试通知。

`deploy-mobile-reading.py` 默认只检查。正式切换前需要已提交源码、候选完整性验证和浏览器验收；切换失败时只回滚仍属于本次发布的 current/fallback，不覆盖并发更新。
