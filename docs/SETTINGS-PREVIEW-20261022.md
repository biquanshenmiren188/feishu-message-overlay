# 电脑／手机独立规则设置页（预览）

新增 `/radar/robot-push/settings/`，保留旧推送设置入口。页面是浏览器本地预览，不读取或修改线上规则，不申请订阅、不发通知，也不修改桌面程序。

电脑屏蔽规则与手机推送规则独立存储、独立保存。每端包含币种、交易所、左右腿及现货／永续组合规则和三级 OI 门槛。手机另有显示条数、合并间隔及通知内容预览。方向固定为左腿买入、右腿卖出，规则内条件同时匹配，不同规则任一命中即拦截。

“记录拦截样例”显式记录当前端模拟结果，显示币种、路线、时间、命中原因和目标端，最多在本浏览器保留最近 200 条。刷新后保留，真实历史尚未接入，不把输入中的暂态判断记为实际发送日志。

通知格式按线上 `compact_rows` 和 `delivery.with_fallback` 核对：标题“雷达”，正文 `HH:MM 百分比 R等级 类型 买所→卖所 币种`，合并最新最多 4 条。全部为虚构样例，经手机规则筛选；不同手机的实际换行、折叠由系统处理。

前端无 fetch、XHR、WebSocket、Service Worker 注册、Notification 或真实消息接口调用。独立 localStorage 命名空间不复用真实配置。

## 正式接入设计（未实施）

同一身份下分别保存 desktop/mobile 配置及版本；使用同一个服务器判断模块，按接收端传入不同规则。桌面在显示和响铃前过滤，手机在合并和发送前过滤；记录判定时使用的规则版本、消息 ID、机会组、原因和接收端，隔离各身份。真实记录由云端持久化，保留策略另行设置，不能依赖网页本地存储。

OI 需核实同交易所、同合约、同永续腿的金额单位及新鲜度；不可把币数量、成交量或另一腿 OI 当成当前腿的持仓金额。多组消息先逐组筛选再聚合，保留原始数据与受控审计。迁移保留旧规则、订阅、PWA 身份和桌面偏好；保存不丢 pending、不重发历史。已发出的系统通知不承诺撤回。

## 发布边界

`scripts/deploy-settings-preview.py` 在既有 guard.lock 内克隆最新静态发布，只添加四个新页面资产与源码索引，原子切换。全量比较已有文件、推送配置／绑定、PWA fallback 和服务 PID，失败回滚 current。不会启动或重启任何服务。

部署提交、验证结果与回滚目录在完成部署后补录。
