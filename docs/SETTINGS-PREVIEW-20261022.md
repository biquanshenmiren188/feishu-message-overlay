# 电脑／手机独立消息设置

入口 `/radar/robot-push/settings/`。手机设置已从旧弹窗迁到独立页面；BOT 的“推送设置”打开新页面。页面沿用主站 Logo、导航、字体及配色，缩小标题、表单与间距，取消筛选样例侧栏。

## 当前范围

手机规则从原推送码读取并保存至原 API，继续使用 revision 校验。初次打开不会导入浏览器旧预览草稿，也不会写入默认值覆盖云端。原订阅、推送码、最低百分比、等级、类型、交易所、间隔、条数保留。通知与推送码管理沿用既有订阅修复、新建及切换流程。

新增手机扩展规则：币种可按交易所设置；交易所＋左腿（买入）／右腿（卖出）＋现货／永续共同匹配；OI 按币种交易所、交易所、全局依次优先，永续双腿分别判断。旧客户端保存时保留它不认识的扩展规则，不会悄悄清空。旧过滤规则的含义不变。后台保留已有强信号逐组解析、去重、内容诊断和消息序号。

OI 使用现有 relay 的 double-v1 同口径持仓金额，按精确 USDT 合约匹配，5 分钟内有效、未来时间容差 30 秒；不借用另一交易所、别名或成交量。已验证 Binance／OKX／Bybit／Bitget／Gate 接口；Aster、Hyperliquid 此共享接口暂未提供同口径值，视作缺失，遵循用户选定的“按屏蔽规则处理／跳过 OI 检查”，不填零。只在设置了门槛时读取 OI，30 秒缓存、有界并发与超时。无 OI 门槛的原设置不调用行情接口。

手机“屏蔽记录”显示当前推送码最近 200 条真实新消息拦截：时间、币种、路线、等级、原因、规则版本。首次接入后开始记录，不回补旧消息，不重发历史。刷新记录不会覆盖未保存的草稿。记录在原方案私有状态中持久化，认证接口仅返回当前推送码的记录。

“推送与预览”展示当前草稿的手机通知格式，最多四条，最新在上；均为固定虚构样例，不发送测试通知。格式 `HH:MM 百分比 R等级 类型 买所→卖所 币种`。系统实际换行、折叠由手机控制。

电脑配置仍独立保存在本浏览器，尚未接入 Windows 小窗。新增“仅屏蔽声音，消息仍接收和显示／屏蔽消息，不显示也不响铃”，仅调整命中规则的处理方案；当前真实小窗行为不变。

## PWA 与发布

已安装 PWA 从 `/radar/push-test/settings/` 进入设置，保持原 manifest ID、scope、worker 和订阅；该路径由 public/settings 符号链接映射到同一份页面。普通浏览器仍使用独立 canonical URL。无需更改 nginx。

发布脚本 `scripts/deploy-integrated-settings.py` 校验实际在线源码基线，复制最新静态 release，替换设置四文件、既有设置控制器以及两处入口缓存版本。仅替换 live.py、preferences.py 和新 advanced_rules.py，重启推送服务；publisher 和桌面软件保持运行。状态迁移先在私有副本中验证两次初始化完全保留数据，发送函数拒绝输出。生产不会人工发通知，不回退 seq 或队列。

失败回滚页面和源码，绝不回写旧状态。如果已有用户保存新扩展规则，保留兼容后端而只回滚页面。设置 API 保留原 8 KiB 上限，前端提交前检查并提示精简。
