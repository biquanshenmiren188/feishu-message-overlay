# 桌面推送码与正式更新 v2026.10.24.1

此前 10 月 23–24 日的消息中台、独立隐藏/静音、卡片管理只存在于开发分支；GitHub 最新正式版仍是 v2026.10.22.3，客户端检查更新无法取得这些功能。本次把现有新功能和桌面推送码绑定纳入同一正式版本。

## 使用方式与范围

- 软件设置新增可选的 8 位推送码。未绑定时接收全部消息和行情卡片；绑定后使用对应码的电脑消息和卡片规则，解绑恢复全部接收。
- 同一码的电脑消息、静音、卡片和手机筛选独立配置；不同码之间隔离。原始管理码保留原有电脑/卡片规则；其他码的电脑/卡片规则从全部接收开始，不复制管理者规则。
- 桌面绑定不创建、迁移或解绑手机通知订阅，也不改手机筛选、通知条数和频率。仍沿用既有桌面签名连接权限。
- 管理卡片需要绑定并成功载入该码的规则。客户端“屏蔽三端”继续只修改草稿，点击保存才提交；网页快捷屏蔽保持原有提交行为，范围限定为当前码。
- 推送码在本机通过 Windows DPAPI 加密，独立于外观设置。绑定验证失败或保存失败保留原绑定；无法解密旧绑定时暂停接收并提示重新绑定/解绑。错误码或规则服务不可用不降级为全部接收。
- 切码、解绑重建接收源并清理上一身份的队列、显示与卡片判定。旧管理窗口不能向新身份提交原草稿。提示音不重播切换前的历史。

## 服务与发布

`pushCode` 只在已验证签名的桌面 control 请求体中传输，不记录正文，不返回到状态或诊断。新协议响应 `pushBinding.protocol=1`；旧客户端无新字段时维持已有行为。每码桌面策略保存在相应 profile 的独立目录，原始方案仍用根目录文件。

先部署后端和网页身份切换处理，再发布客户端。`scripts/deploy-desktop-binding.py` 持锁核对线上版本/文件哈希、增量替换、核对原规则与手机绑定并保留代码回滚。回滚不恢复旧用户数据快照。

正式更新读取 GitHub `/releases/latest`，不会从任意分支安装；提示文案改为“最新正式版”。发布附件名、版本 manifest 和 SHA-256 必须一致。GitHub hosted CI 本次因账户计费/支出限制未启动，使用本机等效验证；不得把该状态描述为远端 CI 通过。

## 验证入口

`scripts/build.ps1 -SelfContained -UpdateVersion v2026.10.24.1` 包括核心检查、WPF、云端读取、卡片/消息布局、币种规则、推送码绑定、四种安装/回退情形和守护恢复。另运行两套后端测试、签名 HTTP 到实际 profile handler 的隔离集成、网页身份切换与权限回归。

发布后使用旧正式版的 `--verify-update-source` 下载校验最新 Release，证明旧客户端可识别并取得新包。真实推送码只通过程序输入；合成测试不写生产筛选、不发人工通知。
